# Rulebook implementation traceability

Last reviewed: 2026-11-16, every row against the code and its suites.

Every printed power has a registered handler: `CardCatalogSuite` fails on a
printed power that no catalog, printed rule or game rule covers. The rule
gaps in the last column are gathered under "Remaining source-cited work"
below; product, test and replay items there name their ROADMAP item.

## Core minor actions

- Combined Rulebook p. 27: the Act menu offers every core minor action at 0 Supply (`gameplay/phases/ActOffers.scala`). Facedown adviser play or discard is `CardPlayProcedure.buildFacedown`. Relic peek, relic reveal and warband movement are `MinorActionProcedures`. Moving warbands to the site needs rule of it and is blocked by Vow of Wandering; moving them to the board must leave one warband, and a Citizen needs the Chancellor's consent (Chancellor's Eye). `MinorActionsSuite` and `FacedownAdviserWalkerSuite` test them.
- Combined Rulebook pp. 20 and 28: adviser play enforces faceup Search placement restrictions, Homeland replacement, next-region discard, and the favor a site play takes (`CardPlay`, `CardSlots`; `CardPlayProcedureSuite`, `HomelandLineSuite`, `CardSlotsSuite`). Card powers change a play through the `SearchPlayAdviser` window.
- New Foundations p. 14: held relics stay facedown until revealed. A site peek is owner-private knowledge (`knowledge.siteRelics`), and it follows the relic when the relic moves; only a move into a deck, the Reliquary or another hidden pile forgets it (`CardKnowledgeMoves`; `application/CardKnowledgeSuite`).

This matrix maps the source-cited rules knowledge layer to executable behavior
and tests. It is a project-management aid, not a second rules reference. Read
the cited summary and source page before implementing a row. Update a row only
when behavior or evidence changes; a similarly named type is not implementation
evidence.

## Status and source conventions

| Status | Meaning |
|---|---|
| **Unimplemented** | No executable rule behavior was found. State/type names alone remain unimplemented. |
| **Partial** | Some bounded behavior is executable, but required rule steps or outcomes are absent. |
| **Implemented** | The bounded behavior is executable, but no focused automated rule test was found. |
| **Tested** | Executable behavior has focused automated tests. |
| **Blocked** | Implementation depends on missing component data or a product/source decision. |

`CR` means the normative *Oath Combined Rulebook*. `NF` means an explicit New
Foundations change/orientation statement; CR remains normative. `A#` refers to
the numbered issue in [`ambiguities.md`](ambiguities.md): B# for “Component-data
dependencies” and F# for “Formalization decisions.”
Implementation paths are abbreviated relative to
`src/main/scala/distantlands/`; suite paths are abbreviated relative to
`src/test/scala/distantlands/`. “Model only” deliberately does not raise a row
above **Unimplemented**.

## Phase 3 playable shell (history)

Phase 3 shipped the playable shell: base actions, private decisions, replay,
and a reviewed fallback that recorded diagnostics for card powers the engine
did not yet run. The fallback and its diagnostics were retired on 2026-10-23
([decision](../superpowers/specs/2026-10/2026-10-23-reviewed-catalog-retirement-decision.md)).
An unregistered handler is now ignored, and every printed power has one.
`GameApplicationServiceStreamSuite` still completes an all-Exile powered game
through round-eight victory and replays it after each Rest.

  `new-foundations-delta.md`, and `ambiguities.md` when source ingestion changes.

  **Partial**; require focused automated evidence before moving to **Tested**.
